# Тест-план

## 1. Введение

Документ описывает подход к тестированию веб-приложения **Job Parser** — дашборда для анализа вакансий с Habr Career и Trudvsem.

## 2. Цели тестирования

- Убедиться в корректности сбора данных с двух источников
- Проверить работу фильтров, сортировки и пагинации
- Проверить корректность метрик и графиков
- Выявить дефекты UI/UX
- Проверить обработку edge-кейсов

## 3. Что тестируется

| Компонент | Вид тестирования |
|-----------|------------------|
| Сбор данных (Habr Career, Trudvsem) | Функциональное, интеграционное |
| Фильтры (город, грейд, удалёнка, зарплата) | Функциональное |
| Сортировка | Функциональное |
| Пагинация | Функциональное |
| Метрики и графики | Функциональное, UI |
| Кэширование | Функциональное |
| UI/UX (шапка, карточки, бейджи) | UI |

## 4. Виды тестирования

- **Функциональное** — проверка соответствия требований
- **UI** — проверка отображения элементов
- **Интеграционное** — проверка взаимодействия с внешними API
- **Регрессионное** — после изменений кода

## 5. Окружение

- Windows 11, Chrome 120+
- Python 3.13, Streamlit 1.40+
- Локальный запуск: `streamlit run app.py`
- Прод: https://job-parser.streamlit.app

## 6. Критерии приёмки

- Все критичные (Critical) и высокие (High) тест-кейсы пройдены
- Нет открытых блокирующих дефектов
- Все метрики рассчитываются корректно
- Фильтры и сортировка работают без перезагрузки данных

## 7. Риски

- API Habr Career и Trudvsem могут быть недоступны — тесты с реальными запросами могут падать не по вине приложения
- Streamlit Cloud может засыпать — первый заход медленный
- Ограничения API по частоте запросов

## 8. Расписание

Тестирование проводилось в процессе разработки приложения — инкрементально, после каждой крупной фичи.
